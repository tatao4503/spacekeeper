Spacekeeper 사용설명서

파일을 삭제하지 않는 macOS 저장공간 정리 도구. 지우는 대신 격리하고, 왜 후보인지 설명하고, 언제든 되돌린다. 만든 사람이 나중에 봐도 알 수 있게 정리한 전체 안내.

🟢 30초 첫 사용 (이것만 알면 됨)

  1. 실행 — 런치패드나 Spotlight(⌘Space)에서 Spacekeeper 검색 → 실행. 창이 열리며 이 Mac 안에서만 도는 로컬 대시보드가 뜬다.
  2. 위치 고르기 — 상단 분석할 위치에서 홈 폴더 전체(또는 다운로드/데스크탑/직접 경로).
  3. 분석 시작 — 버튼을 누르면 큰 파일·오래된 다운로드·다시 만들 수 있는 캐시를 분류해서 보여준다. 이 단계에서 파일은 하나도 바뀌지 않는다.
  4. 고르기 — 항목마다 이유·주의·위험도가 붙어 있다. 지울 것만 체크. 자신 없으면 낮은 위험 모두 선택 또는 안전 항목 바로 정리.
  5. 격리 — 선택 항목 격리. 파일은 삭제가 아니라 격리함으로 이동된다. 마음 바뀌면 격리함에서 원위치로 복원.

여기까지가 95%. 나머지는 필요할 때만 보면 된다.

🛡️ 이 앱의 4가지 원칙 (왜 다른가)

  • 아무것도 파괴하지 않는다. "정리"는 파일을 ~/.spacekeeper/quarantine/로 옮기고 원래 위치를 기록하는 것. 복원은 한 번의 클릭. 격리함 비우기도 영구 삭제가 아니라 macOS 휴지통으로 보내므로, 그 단계까지 되돌릴 수 있다.
  • 모든 항목이 스스로를 설명한다. 후보마다 이유("Cargo가 다시 만들 수 있음")·주의·위험도가 붙는다. "정크 12.4GB" 같은 불투명한 덩어리는 없다.
  • 정직한 숫자. 크기는 논리 크기가 아니라 실제 할당 블록(st_blocks)으로 잰다. 희소 파일·클라우드 자리표시자가 숫자를 부풀리지 않는다. APFS 복제 때문에 실제 확보량이 더 적을 수 있다는 점도 화면에서 미리 알려준다.
  • 완전한 로컬. 외부 네트워크 통신 없음, 계정 없음, 텔레메트리 없음. 대시보드는 루프백 주소에서만 요청을 받고, 실행할 때마다 새 인증 토큰으로 API 요청을 확인한다. 코드가 공개돼 있으니 직접 확인할 수 있다.

🧭 화면 둘러보기

왼쪽 사이드바는 네 묶음으로 나뉜다.

개요

화면하는 일
공간 요약메인 대시보드. 위치를 정해 분석하고, 되찾을 수 있는 용량·위험도 분포·정리 후보 목록을 본다. 도넛은 남은 공간, 큰 숫자는 정리 후보 용량.
디스크 지도어떤 폴더가 공간을 많이 쓰는지 크기 블록(트리맵)으로 한눈에. 블록을 눌러 안으로 들어간다.

정리

화면하는 일
대용량 파일정한 크기(10MB~1GB) 이상 파일을 찾아 종류별로. 항목을 펼치면 출처·마지막 사용 같은 단서가 보인다.
중복 파일내용이 완전히 같은 파일을 묶어서. 그룹마다 하나는 원본으로 남겨 둔다.
비슷한 사진크기·화질이 달라도 눈으로 같아 보이는 사진을 묶어 준다(지각적 비교). 그룹의 가장 큰 파일이 원본.
결정 도우미지울지 말지 애매한 큰 파일 모음. 펼치면 출처·마지막 사용·다른 곳의 복사본 같은 단서만 중립적으로 보여준다. 판단은 직접.

앱 · 시스템

화면하는 일
앱과 관련 파일설치된 앱 + 그 앱이 남긴 지원·캐시·설정 파일을 함께. 앱을 펼치면 관련 파일이 인라인으로 보인다.
브라우저·메일Safari·Chrome·Firefox·Edge·Arc와 메일이 쌓아 둔 캐시를 찾는다.
시작 프로그램로그인할 때 자동으로 켜지는 항목. 끄면 설정 파일을 격리함으로 옮겨 실행을 멈추고, 복원하면 다시 켜진다. (시스템 영역 항목은 읽기 전용)

보관 · 관리

화면하는 일
격리함옮겨 둔 항목 보관소. 원위치로 복원하거나, 직접 확인한 것만 macOS 휴지통으로 보낸다.
자동 정리기본은 알림만 제공. 직접 켜고 한 번 더 확인한 경우에만 패키지 다운로드·도구 캐시를 자동 격리하도록 예약.
환경 진단보호 폴더 읽기·격리·복원이 실제로 동작하는지 점검.

♻️ 정리 흐름 — 스캔에서 복구까지

① 분석 → ② 선택 → ③ 격리 → ④ 복원 또는 휴지통

  1. 분석은 읽기만 한다. 파일을 만지지 않는다.
  2. 선택: 위험도 필터(낮은 위험 / 확인 필요 / 높은 주의)와 검색으로 좁힌다.
  3. 격리: 선택 항목이 ~/.spacekeeper/quarantine/로 이동. 원래 경로가 manifest에 기록된다. 이 시점엔 저장 공간이 늘지 않는다(아직 되돌릴 수 있으니까).
  4. 복원: 격리함에서 원래 자리로 정확히 되돌린다. 또는 휴지통으로 보내면 그제서야 실제 여유 공간이 늘어난다 — 그마저도 Finder에서 비우기 전까진 복구 가능.

격리함 위치는 ~/.spacekeeper/quarantine/. 무슨 일이 있어도 여기 있는 것은 앱이 지우지 않는다. 최종 삭제는 오직 사용자가 Finder에서 휴지통을 비울 때.

⚙️ 자동 정리

  • 자동 스캔·정리 켜기: macOS 백그라운드 에이전트로 주기 실행.
  • 실행 주기: 매일(24h) / 매주(168h) / 매월(30일).
  • 재생성 캐시 자동 격리: 패키지 다운로드·도구 캐시만 격리(기본 꺼짐 — 켜고 확인해야 자동 이동). 프로젝트 node_modules, 빌드 산출물, 시뮬레이터 데이터는 자동 대상에서 제외.
  • 완료 알림 받기: 자동 정리가 끝나면 macOS 알림.

자동 정리도 삭제가 아니라 격리다. 자동으로 사라지는 파일은 없다.

▶️ 실행 · 설치 · 권한

실행하기

  • 런치패드/Spotlight에서 Spacekeeper → 실행
  • 또는 응용 프로그램 폴더에서 Spacekeeper.app 더블클릭
  • 또는 터미널: open -a Spacekeeper

"확인되지 않은 개발자" 경고가 뜨면 (직접 서명한 앱이라 macOS Gatekeeper가 처음 한 번 막을 수 있음):

  • 방법 A — Spacekeeper.app 우클릭 → 열기 → 다시 열기. 한 번만 하면 이후엔 그냥 열린다.
  • 방법 B — 시스템 설정 → 개인정보 보호 및 보안 → 아래쪽 "확인 없이 열기".

전체 디스크 접근 권한

데스크탑·문서·다운로드는 macOS가 보호하는 폴더다. 이 폴더까지 분석하려면 시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한에서 Spacekeeper를 허용한 뒤 앱을 다시 실행한다. 허용하지 않아도 나머지 폴더는 분석된다. 환경 진단 화면에서 현재 접근 상태를 확인할 수 있다.

개발자용 — 소스에서 바로 실행

앱 번들 없이 UI만 보고 싶을 때:

cd spacekeeper && python3 -m spacekeeper --serve → 브라우저에서 http://127.0.0.1:8765

표준 라이브러리만 쓰므로 별도 설치가 필요 없다.

🌐 언어

사이드바 아래 한국어 / English 스위치로 즉시 전환. 화면·설명·이유 문구까지 전부 번역된다. 라이트/다크 테마는 macOS 시스템 외관 설정을 따라간다.

⚠️ 문제 해결

증상이유 / 해결
보호 폴더가 비어 보이거나 분석이 막힘전체 디스크 접근 권한 미허용. 위 안내대로 허용 후 재실행.
격리했는데 "시스템 데이터"가 그대로거나 커 보임macOS 저장공간 UI의 재계산 지연이다. 실제 여유는 터미널 df -h로 확인. 격리는 휴지통을 비워야 실여유로 반영된다.
클라우드 폴더 분석이 느리거나 멈춘 듯함iCloud/Google Drive 등은 자리표시자를 실제로 받아오려다 느려질 수 있다. Spacekeeper는 클라우드 컨테이너를 건너뛰지만, 제외 경로에 직접 추가해도 된다.
실수로 잘못 격리함격리함 → 해당 항목 복원. 원래 경로로 정확히 되돌아간다.
